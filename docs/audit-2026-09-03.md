# Laporan Audit Proyek PIB Penilaian

Tanggal audit: 3 September 2026  
Basis pemeriksaan: commit `6b040f6` (`Build Phase 1`) dan kondisi worktree saat audit.

## 1. Ringkasan Eksekutif

Proyek sudah memiliki fondasi aplikasi yang berjalan: Next.js 15, TypeScript, SQLite melalui `better-sqlite3`, autentikasi berbasis cookie bertanda tangan, modul penilaian, rekap, ekspor, backup/restore, PWA, dan test domain.

Status teknis saat audit:

- `npm test`: lulus, 6 file test dan 14 test.
- `npx tsc --noEmit`: lulus.
- `npm run build`: lulus; 35 route berhasil dibuat.
- `npm run perf:check`: gagal; aset client terukur 11.77 MB, di atas baseline 5 MB.
- `npm run lint`: belum menjadi bukti audit karena pemeriksaan dibatalkan saat dijalankan.

Kesimpulan: aplikasi layak untuk dilanjutkan ke hardening dan uji penerimaan, tetapi belum layak disebut rilis stabil. Risiko utama ada pada pengelolaan secret produksi, perlindungan dan isi backup, ukuran bundle halaman siswa, dan belum adanya pengujian end-to-end untuk alur data penting.

## 2. Pengerjaan yang Sudah Dilakukan

### Fondasi aplikasi

- Struktur Next.js App Router dan TypeScript sudah tersedia.
- Database SQLite dibuat dengan foreign key aktif dan mode WAL.
- Schema mencakup user, tahun ajaran, kelas, siswa, kurikulum, assessment, scores, settings, audit log, dan operasi sinkronisasi.
- Seed/setup database disediakan melalui `npm run db:setup`.
- Konfigurasi build dan test sudah tersedia di `package.json`, `tsconfig.json`, dan `vitest.config.ts`.

### Autentikasi dan akses

- Login, setup akun pertama, logout, cek user aktif, dan ubah password sudah tersedia.
- Session berisi `userId`, expiry, dan signature HMAC.
- Middleware saat ini mencakup halaman internal (`dashboard`, `master-data`, `assessment`, `recap`, `reports`, `students`, `account`) serta seluruh `/api`.
- Session di edge dan server memvalidasi signature serta expiry; parser server menangani cookie malformed.

### Fitur domain dan data

- Rumus nilai `90 - jumlah kesalahan` dan nilai kosong sebagai `NULL` sudah diwakili oleh modul domain dan test.
- Rekap progress dan filter memiliki modul terpisah.
- Endpoint CRUD untuk tahun ajaran, kelas, siswa, template, bab, subbab, assessment, settings, dan score tersedia.
- Endpoint sinkronisasi memiliki idempotency berbasis operation id dan deteksi konflik melalui `baseUpdatedAt`.

### Laporan dan PWA

- Ekspor Excel memiliki sheet detail, rekap siswa, dan rekap kelas.
- Ekspor PDF mendukung pemisahan halaman dan teks panjang melalui `splitTextToSize`.
- Query laporan memakai kontrak filter bersama melalui `lib/filters.ts` dan `lib/report-query.ts`.
- Manifest dan service worker tersedia.
- Service worker membatasi cache pada shell dan aset static, tidak mencache route API, dan membersihkan cache versi lama.

## 4. Temuan Audit dan Masukan

### Prioritas tinggi

#### H1. Secret produksi masih memiliki fallback default dan validasi environment tidak terhubung

`lib/session.ts` dan `lib/session-edge.ts` menggunakan `development-only-secret-change-me` ketika `SESSION_SECRET` tidak tersedia. `lib/env.ts` memang mendefinisikan schema, tetapi hasil `env` tidak digunakan oleh jalur session maupun database. Akibatnya, deployment yang lupa mengisi secret dapat berjalan dengan secret publik yang diketahui.

Dampak: token session dapat dipalsukan oleh pihak yang mengetahui fallback secret, terutama bila aplikasi diekspos di luar komputer lokal.

Masukan:

- Hapus fallback untuk production.
- Gagal startup bila `NODE_ENV=production` dan `SESSION_SECRET` belum diisi dengan secret acak yang memadai.
- Gunakan satu sumber konfigurasi untuk session dan database.
- Tambahkan test konfigurasi production dan dokumentasikan rotasi secret.

#### H2. Backup mengikutsertakan `password_hash`

`app/api/backup/route.ts` mengekspor seluruh kolom tabel `users`, termasuk hash password. Hash bukan password plaintext, tetapi tetap merupakan data sensitif dan dapat menjadi target offline cracking bila file backup bocor.

Masukan:

- Jangan ekspor `password_hash` ke backup operasional, atau enkripsi backup dengan kunci terpisah.
- Batasi backup/restore dengan guard server-side yang eksplisit dan role yang sesuai, selain middleware.
- Tambahkan audit log untuk download dan restore.
- Uji bahwa backup tidak mengandung hash password dan restore tetap dapat mempertahankan akun secara aman.

### Prioritas menengah

#### M1. Performance check gagal karena bundle/assets terlalu besar

`npm run perf:check` menghasilkan 11.77 MB aset client, melewati baseline 5 MB. Halaman `/students` mengimpor `exceljs` langsung dari client, sehingga dependency spreadsheet berpotensi ikut masuk ke bundle browser.

Masukan:

- Pindahkan parsing Excel ke endpoint/server action atau lazy-load hanya saat pengguna membuka impor.
- Ukur ukuran JavaScript yang benar-benar dikirim per route, bukan hanya total direktori static.
- Tetapkan baseline terpisah untuk initial load dan fitur impor.
- Jadikan performance check sebagai gate CI setelah baseline diperbaiki.

#### M2. Migrasi SQLite belum menjadi sistem migrasi berurutan

`lib/db.ts` membuat seluruh schema saat module dimuat dan hanya memasukkan versi `1` ke `schema_migrations`. Belum ada daftar migrasi, pemeriksaan versi saat ini, atau eksekusi perubahan schema bertahap untuk database lama.

Masukan:

- Buat runner migrasi dengan versi monotonik dan transaksi per migrasi.
- Uji database kosong dan database dari versi sebelumnya.
- Pastikan perubahan schema tidak bergantung pada import route aplikasi.
- Dokumentasikan prosedur upgrade dan rollback/backup sebelum upgrade.

#### M3. Test belum mencakup alur yang paling berisiko

Test otomatis saat ini berfokus pada domain dan session: 14 test lulus. Belum terlihat coverage terotomasi untuk login HTTP, middleware, CRUD API, impor siswa, ekspor Excel/PDF, backup/restore, sync conflict, responsive UI, dan aksesibilitas.

Masukan:

- Tambahkan API integration test untuk autentikasi, otorisasi, score, backup, restore, dan sync.
- Tambahkan test regresi untuk filter yang sama pada rekap, Excel, dan PDF.
- Tambahkan browser smoke test untuk login, input nilai, impor siswa, laporan, dan logout.
- Tambahkan kasus database kosong, data besar, teks panjang, nilai kosong, dan konflik sync.

### Prioritas rendah

#### L1. Dokumentasi status belum konsisten dengan bukti audit

`docs/todo.md` menandai hampir seluruh item Phase 2 sebagai selesai, termasuk API test, migrasi, impor, ekspor, offline, responsive, dan accessibility. Namun test yang ditemukan masih 14 unit test, checklist rilis masih mencentang uji browser, backup/restore, laporan besar, dan accessibility sebagai belum selesai, serta performance check masih gagal.

Masukan:

- Ubah checklist menjadi sumber status yang disepakati.
- Tandai item sebagai selesai hanya setelah ada bukti test atau acceptance check.
- Pisahkan “kode tersedia” dari “sudah diverifikasi”.
- Perbarui `docs/todo.md` berdasarkan hasil audit ini agar tidak memberi sinyal kesiapan yang berlebihan.

#### L2. Worktree memiliki perubahan file SQLite runtime

`git status` menunjukkan `pib.sqlite-shm` dan `pib.sqlite-wal` berubah. File tersebut adalah artefak runtime SQLite WAL, bukan sumber perubahan fitur.

Masukan:

- Jangan menjadikan database runtime sebagai artefak perubahan aplikasi.
- Pastikan file SQLite lokal/WAL masuk aturan ignore atau gunakan database fixture terpisah untuk test.
- Backup data demo secara eksplisit bila memang diperlukan untuk instalasi baru.

## 5. Hal yang Sudah Lebih Baik dari Audit Phase 2

Beberapa temuan pada `docs/audit-phase-2.md` sudah berubah atau terselesaikan dalam implementasi sekarang:

- Middleware sekarang mencakup route internal utama dan memvalidasi session, bukan hanya keberadaan cookie.
- Parser session server sudah menangani signature dengan panjang berbeda dan payload malformed.
- Logout, expiry session, ubah password, serta route account sudah tersedia.
- Filter laporan sudah digunakan oleh query bersama yang dipakai Excel dan PDF.
- Service worker tidak lagi mencache API/auth secara umum dan sudah membersihkan cache lama.
- Build dan test sekarang menunjukkan fondasi yang lebih luas daripada baseline audit lama.

Temuan lama yang masih perlu dibuktikan atau diperiksa ulang adalah kelengkapan UI impor/CRUD siswa, integrasi operation queue ke UI offline, kelengkapan format PDF/Excel terhadap spesifikasi bisnis, serta atomicity dan kontrol akses restore.

## 6. Rencana Tindak Lanjut yang Disarankan

### P0: sebelum deployment non-lokal

1. Hilangkan fallback `SESSION_SECRET` untuk production dan wiring `lib/env.ts` ke seluruh jalur konfigurasi.
2. Hilangkan `password_hash` dari backup atau enkripsi arsip.
3. Tambahkan guard eksplisit untuk backup/restore dan audit log.
4. Tambahkan integration test untuk auth, middleware, backup, dan restore.

### P1: sebelum rilis ke guru

1. Lazy-load atau pindahkan `exceljs` dari bundle awal halaman siswa.
2. Bangun runner migrasi SQLite berversi.
3. Uji alur impor siswa, penilaian, sync conflict, dan ekspor dengan data nyata/berukuran besar.
4. Selaraskan `docs/todo.md` dan `docs/checklist-rilis.md` dengan bukti verifikasi.

### P2: peningkatan kualitas

1. Tambahkan browser smoke test desktop dan mobile.
2. Tambahkan pemeriksaan keyboard, focus, kontras, dan pesan error.
3. Lengkapi observability sederhana untuk kegagalan sync, restore, dan export.
4. Tetapkan baseline performance yang dapat direproduksi per route.

## 7. Kriteria Audit Berikutnya

Audit berikutnya dianggap berhasil bila:

- Production startup menolak secret default atau secret yang tidak valid.
- Backup tidak memuat credential sensitif dan restore memiliki guard eksplisit.
- `npm test`, typecheck, lint, build, dan performance check lulus.
- API integration test dan browser smoke test mencakup alur kritis.
- Migrasi database dapat dijalankan dari database kosong dan versi lama.
- Status dokumentasi konsisten dengan bukti implementasi dan test.
